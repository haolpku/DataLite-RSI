# HLE With-Tools Docker Environment

This image runs the source reviewed under
[`benchmarks/hle/withtools/src/hle_eval`](../../benchmarks/hle/withtools/src/hle_eval).
It evaluates exactly one HLE sample per container. The solver and judge use
OpenAI-compatible chat-completions endpoints; `web_search`, `web_fetch`, and
Python execution are available to the solver.

The image contains neither HLE data, model weights, nor credentials. Mount data
and configuration at runtime. Provider keys are read only from the environment
variables named by the configuration.

## Build

Run from the repository root:

```bash
docker build -f docker/llm-hle-with-tools/Dockerfile \
  -t datalite-rsi-hle-with-tools:0.1.0 .
```

The image is Linux/amd64-compatible and requires Docker plus outbound network
access for the configured model, judge, search provider, and fetched pages. It
does not require a GPU. Python generated by the model is run as UID/GID 65534,
but shares the container network, so only run it in an appropriately isolated
Docker environment.

## Run one sample

Copy `config.example.json` outside the repository, replace endpoint and model
placeholders, and mount an authorized HLE JSONL file at `/data`. The config's
`sample_id` is overridden by the command line.

```bash
docker run --rm \
  -e MODEL_API_KEY \
  -e JUDGE_API_KEY \
  -e TAVILY_API_KEY \
  -v "$PWD/eval.json:/config/eval.json:ro" \
  -v "$PWD/data:/data:ro" \
  -v "$PWD/output:/output" \
  datalite-rsi-hle-with-tools:0.1.0 \
  --config /config/eval.json --sample-id <sample-id>
```

The HLE dataset is gated. Obtain access from its provider and keep exported
records outside Git. The runner writes one JSON object to
`/output/results.jsonl`; use `benchmarks/hle/withtools/evaluator.py` to compute
offline metrics.

## Batch runs

`benchmarks/hle/withtools/scripts/run_batches.sh` starts one container per
sample and captures per-container logs, exit codes, host load, and Docker
resource snapshots. It accepts an environment file, sample-ID file, runtime
configuration, mounted data directory, and output root:

```bash
IMAGE=datalite-rsi-hle-with-tools:0.1.0 \
BATCH_SIZES=1,4,5,10 \
bash benchmarks/hle/withtools/scripts/run_batches.sh \
  /path/to/provider.env /path/to/sample_ids.txt /path/to/eval.json \
  /path/to/data /path/to/output
```

`BATCH_SIZES` must sum to the number of non-empty sample IDs. These batch
artifacts are local run evidence, not benchmark source. Merge the per-container
output before aggregation; failed records remain in the merged JSONL so the
completion rate remains meaningful:

```bash
python benchmarks/hle/withtools/scripts/merge_results.py \
  /path/to/output/<run-id> /path/to/merged-results.jsonl
python benchmarks/hle/withtools/evaluator.py \
  --predictions /path/to/merged-results.jsonl --output /path/to/metrics.json
```

The benchmark manifest leaves `container_image` unset. Build this image locally
from the reviewed repository commit before running an evaluation.
