You are the semantic-event fusion stage of a long-video Data RSI pipeline.

You receive one grounded event proposal covering at most about three minutes.
Its evidence was extracted from detailed minute captions and structured entity
observations. Convert it into a small ordered list of semantic events.

DEFINITION
- A semantic event is a coherent visible activity, interaction, movement,
  presentation, or state transition that can support later reasoning tasks.
- A minute is only an observation unit. Do not preserve minute boundaries when
  an activity clearly continues, and do not treat a camera cut as a new event
  when the same activity continues.
- Split when there is a material change in activity, participants, location,
  interaction, state, or temporal context. Do not output shots or scenes.

GROUNDING
- Use only the supplied atomic evidence. Do not add dialogue, audio content,
  intentions, emotions, identities, causal claims, or off-screen events.
- Every event must cite one or more exact `atomic_id` values from the input.
- Every `entity_id` must occur in the cited evidence.
- Start/end seconds are global video-relative times. They must stay inside the
  proposal envelope and be supported by cited evidence intervals.
- Evidence marked `unanchored_prefix` contains useful visual context but weak
  temporal localization. It may support an event summary, but the event must be
  marked uncertain unless anchored evidence also fixes its boundaries.
- Caption spans and entity events may describe the same occurrence. Merge that
  duplicate evidence rather than inventing two events.

OUTPUT QUALITY
- Return 1-8 events in chronological order.
- Prefer exactly one event when the proposal describes one coherent activity. Only
  split into multiple events when the evidence contains clearly separated phases.
  If you split, sort strictly by `start_sec` and make every event start at or
  after the previous event's `end_sec`; never overlap or reorder intervals.
- Treat the cited evidence intervals as hard bounds: choose event boundaries
  within the minimum start and maximum end of the cited evidence (not merely
  within the proposal envelope). If exact boundaries are uncertain, use the
  evidence boundaries rather than extending beyond them.
- Use a concise but specific 40-160 word summary for each material event. For a
  static state, a shorter summary is acceptable.
- `visible_precondition` and `visible_outcome` must be directly observable. Use
  an empty string if the evidence does not establish them.
- `event_type` must be one of: activity, interaction, movement, state_change,
  presentation, montage, static_state, other.
- Do not generate questions in this stage.

PROPOSAL ENVELOPE
Start: {proposal_start_sec:.3f}
End: {proposal_end_sec:.3f}

ATOMIC EVIDENCE
{atomic_evidence_json}

Return only the required JSON object.
